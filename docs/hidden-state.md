# 实际收纳状态

## 0.1.20 Assessment Mode 状态

- macOS 27 及后续版本不再创建遮罩或透明状态项。“已收纳”表示系统 Assessment Mode 已接受当前允许列表，并隐藏了目标菜单栏宿主应用。
- 隐藏后原生菜单栏会立即重新排版并回收宽度，因此不会保留黑框、透明块或中间空槽。
- 同一宿主应用的多个菜单项只能整组显示或隐藏。修改其中一个项目的规则时，MacBarTuck 会同步该应用的同组项目，避免界面状态与系统结果不一致。
- 普通刷新在允许列表未变化时不会替换活动 assertion。点击托盘项目会先临时显示该应用整组菜单项；“重新收纳”重新应用过滤，关闭收纳、选择“全部显示”或退出应用会释放 assertion。
- 无法解析宿主应用的项目不会被错误隐藏，并会显示为收纳失败；只有 assertion 成功后才会发布“已收纳”状态。

## 0.1.19 原生溢出状态

- macOS 27 及后续版本不再创建逐项遮罩窗口。“已收纳”表示目标项目已经移动到 MacBarTuck 原生分隔项左侧，并由分隔项宽度推入系统菜单栏溢出区。
- 保留项目、系统固定项目和 MacBarTuck 图标位于分隔项右侧，保持连续排列。原图标槽位会被系统重新排版回收，不应留下黑框、透明块或中间空洞。
- 布局事务按当前真实顺序生成一次移动计划；每个移动必须连续两次读到稳定相邻位置才算成功。失败会按事务起始顺序回滚，不提前把项目加入托盘。
- 普通刷新不会移动菜单栏。重复点击“应用显示方式”在规则和分隔项数量不变时直接返回；关闭收纳、选择“全部显示”或退出应用会恢复本次启动前记录的顺序。
- 菜单栏顺序由 macOS 全局维护，因此主屏和扩展屏共享同一逻辑排列；分隔项宽度按已连接显示器中最受限的状态区计算。

## 0.1.18 背景状态

- 菜单栏空白区域由当前显示器的真实背景补片覆盖，不再使用带深色 tint 的独立系统材质窗口。
- 切换 Space、唤醒、会话重新激活或显示器配置变化时，仅更新已有遮罩的背景图；窗口位置和收纳状态不变。
- 若某次屏幕截图暂时失败，继续保留上一张有效补片，不把已收纳项目改成黑框、透明块或失败状态。

## 0.1.17 macOS 27 状态语义

- 在 macOS 27 及后续版本，“已收纳”表示目标在所有活动显示器上的遮罩窗口均已创建、位置已核对且当前可见；只有保存了“收起”规则但遮罩未建立时仍显示待应用或失败，不会提前进入托盘。
- 原生系统图标仍由所属应用维护在遮罩下方，MacBarTuck 不再修改复合菜单栏宿主的位置。用户看到的菜单栏位置应为空白，托盘继续显示应用自身图标用于识别和激活。
- 关闭收纳、选择“全部显示”、规则改为常显、项目退出、屏幕录制权限失效或 MacBarTuck 退出时，遮罩会同步移除，原图标恢复可见。
- 主屏和扩展屏必须同时建立遮罩才算成功；任何一块显示器缺少可信位置都会标记为收纳失败，不会宣称部分成功。

## 0.1.7 修正

- 系统 Clock 是保留项，旧隐藏规则不会覆盖它；Wi-Fi 等其他可配置项保持原规则语义。
- 逻辑项目汇总各屏幕窗口的真实可见状态。仅全部已确认隐藏时标记已收起；一份可见则为部分可见；缺失窗口记录为待确认。
- 托盘不再依据期望规则提前加入项目。列表保留显示方式，并单独显示已收起、待收起、收起失败或待确认。
- 布局结束读回真实窗口，失败时不会宣称收纳成功，刷新仍为只读。
- 增加旧行为先失败的 Store 回归：一个仍可见但规则为收起的项目不能出现在托盘中。
